## 1. Task Objective

The objective of this task is to organize and integrate all required Milestone 1 deliverables into a consistent project submission.

The final submission must include the written project report, the required analysis and design diagrams, and the native Visual Paradigm project file.

## 2. Required Deliverables

### A. Project Report

The report should contain the following sections:

- Project introduction and overview.
- System scope and assumptions.
- Functional requirements and system analysis.
- Data Flow Diagrams (DFDs).
- Use Case Diagrams.
- Four complex Use Case Specifications.
- Design Class Diagram.
- Explanations and consistency checks for the models.
- Scrum activities and GitHub evidence, where required.

### B. Data Flow Diagrams

Verify that the required DFDs are included:

- DFD Level 0.
- DFD Level 1.
- DFD Level 2.
- Appropriate external entities, processes, data stores, and data flows.
- Gane-Sarson notation.
- Balancing between parent and child diagrams.

### C. Use Case and Design Models

Verify the availability of:

- Required Use Case Diagrams.
- Four complex Use Case Specifications.
- Design Class Diagram.
- Consistent actor names, operations, entities, and relationships.

### D. Native Visual Paradigm Project

The submission must include the original editable Visual Paradigm project file with the .vpp extension.

The file must contain the required diagrams and must open successfully in Visual Paradigm.

Screenshots or exported images alone are not substitutes for the native .vpp file.

## 4. Consistency Verification

The following items must be checked before the task is considered complete:

1. The report describes the same system scope as the diagrams.
2. Requirements are reflected in the relevant analysis models.
3. DFD processes, data stores, entities, and flows use consistent names.
4. Inputs and outputs remain balanced between DFD levels.
5. Use Case Specifications match the corresponding Use Case Diagrams.
6. The Design Class Diagram supports the documented system requirements.
7. The native Visual Paradigm project matches the diagrams presented in the report.

## 5. Identified Risks

| Risk | Required Action |
| --- | --- |
| Missing diagram | Add the required diagram before submission. |
| Inconsistent data flow names | Standardize names across related DFD levels. |
| DFD balancing error | Compare parent and child inputs and outputs. |
| Missing use case specification | Complete and review the required specification. |
| Report and .vpp mismatch | Update the outdated model or report section. |
| Invalid or missing .vpp file | Open and verify the native project file. |
| Missing GitHub evidence | Collect links and screenshots of actual activities. |

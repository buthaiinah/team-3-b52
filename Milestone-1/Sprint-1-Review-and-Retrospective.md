## 1. Sprint 1 Review

### Sprint Goal

Review the initial requirements, scope, and analysis models for the PearlMart Inventory Management System.

The review focuses on the consistency and completeness of the project documentation, especially the Data Flow Diagrams (DFDs).

### Deliverables Reviewed

The following deliverables were considered during the Sprint 1 review:

- Requirements and project scope
- DFD Level 0
- DFD Level 1
- DFD Level 2
- Available use case documentation
- Related GitHub Issues and Pull Requests

### Review Results

**Completed or Available Work**

- Initial project requirements and scope documentation were prepared.
- DFD documentation for inventory operations was added.
- DFD Level 1 and related data stores were documented.
- Sale Level 2 DFD and balancing documentation were added.
- Team members used GitHub Issues and Pull Requests to organize, submit, and review project changes.
- The Sprint 1 Review and Retrospective document was created and reviewed.

**Work Requiring Further Validation**

- Confirm that all required DFD diagrams are consistent with the documented processes.
- Verify that external inputs and outputs remain balanced between DFD levels.
- Review and standardize data flow names across diagrams.
- Complete the final validation of the available analysis and design deliverables.

### Issues and Inconsistencies

The team identified the following areas for improvement:

1. Some data flow names need to be standardized across different DFD levels.
2. Cross-diagram consistency checks should be completed before final approval.
3. DFD balancing should be verified between Level 0, Level 1, and Level 2.
4. Any identified corrections should be documented and reviewed through GitHub.

### Sprint 1 Review Conclusion

Sprint 1 established the initial project documentation and DFD models.

The team reviewed the available work and identified improvements required before finalizing the analysis and design deliverables.

The remaining consistency and balancing checks will be addressed during Sprint 2.

## 2. Sprint 1 Retrospective

### What Went Well?

- Team members collaborated on preparing and reviewing project documentation.
- GitHub Issues helped organize project tasks and responsibilities.
- Pull Requests provided a clear process for submitting and reviewing changes.
- Team discussions helped identify areas requiring improvement.
- The team documented review findings and agreed on follow-up actions.

### What Could Be Improved?

- Data flow names should remain consistent across all DFD levels.
- Diagram balancing should be checked before approving final deliverables.
- Team members should coordinate cross-diagram reviews more closely.
- Review results and required corrections should be documented clearly.

### Lessons Learned

- Consistent naming improves the clarity of DFD models.
- Reviewing related diagrams together helps identify missing or inconsistent data flows.
- Pull Request reviews support teamwork and documentation quality.
- Recording improvement actions makes it easier to plan the next Sprint.

## 3. Sprint 2 Improvement Plan

### Improvement Objective

Improve the consistency, balancing, and completeness of the PearlMart analysis and design documentation before Milestone 1 submission.

### Action Items

**Action 1: Review DFDs Together**

- Compare the available Level 0, Level 1, and Level 2 DFDs.
- Identify missing, duplicated, or inconsistent data flows.
- Record the results of the review.

**Action 2: Standardize Data Flow Names**

- Use consistent terminology across related diagrams.
- Correct naming differences identified during the Sprint 1 review.
- Ensure the documentation matches the updated diagrams.

**Action 3: Verify DFD Balancing**

- Check that inputs and outputs remain consistent between parent and child processes.
- Review the decomposition of the Sale process.
- Record any required corrections.

**Action 4: Document and Review Corrections**

- Update the affected diagrams or documentation.
- Link changes to the relevant GitHub Issues.
- Submit changes through Pull Requests.
- Request a teammate review before merging.
